    图表（ob-mermaid, ob-dot, ob-plantuml）

    org-extensions-diagrams

    稳定性：稳定（org-extensions-stability）

    diagrams 扩展将图表源代码块渲染为图片：支持 mermaid（使用 mermaid-cli 的 mmdc，类似第三方 ob-mermaid）、dot（Graphviz，类似 Emacs 的 ob-dot）以及内置的 plantuml 移植版（org-babel-languages）：

    require("org").setup({
  extensions = { diagrams = { render_on_save = true } },
})

    在代码块上按 C-c C-c 会将图表写入其 :file 并插入 [[file:...]] 结果，与任何 babel 语言一样（两种语言默认使用 :results file :exports results）：

    #+begin_src mermaid :file flow.png :theme dark
flowchart LR
  A --> B
#+end_src

#+begin_src dot :file deps.svg :var color="red"
digraph { a [color=$color]; a -> b }
#+end_src

    mermaid 接受 ob-mermaid 的头部参数 :theme、:background-color、:width、:height、:scale、:mermaid-config-file、:css-file 和 :puppeteer-config-file（ob-mermaid 的拼写 :pupeteer-config-file 也有效）。dot 运行 CMD IN CMDLINE -o OUT，类似 ob-dot：:cmd（默认 dot）、:cmdline（默认 -T 加上 :file 的扩展名），$NAME 由 :var NAME 替换。plantuml 保留其在 babel.languages.plantuml 中的选项；当未设置 jar_path 但安装了 plantuml 命令时，将使用该命令。

    超越 Emacs

    • 没有 :file 的块会生成 output_dir/LANG-HASH8.EXT（HASH8 是内容哈希的开头；EXT 是 :file-ext 或 format），相对于 org 文件的目录或 :dir。Emacs 会报错；设置 auto_file = false 可获得该行为。
    • 渲染的图表会缓存在 cache_dir 中，键为语言、命令和选项、输出格式以及展开后内容的哈希。未更改的图表会从缓存复制，而不是重新渲染。对于 plantuml，键还包括文本通过 !include（!include_once、!include_many、!includesub；本地文件，最多四层）引入的文件，因此编辑这些文件会触发重新渲染。:Org diagrams_rerender 不使用缓存渲染当前块，:Org diagrams_clear_cache 清空缓存。启动时，缓存会删除 cache_max_age 天未使用的条目，然后删除超出 cache_max_size 兆字节的最久未使用条目。两者都只影响缓存条目（以哈希命名的文件）；cache_dir 中的其他文件不受影响。
    • 启用 auto_preview（默认）时，块运行后会在内联显示结果图片，前提是图像后端可用（org-images；SVG 需要 ImageMagick）。
    • 启用 render_on_save 时，保存 org 缓冲区后会渲染其中的所有图表块，在后台逐个处理，因此 mmdc 或 dot 运行时 Neovim 仍保持响应。完成后，如果只有结果发生变化，缓冲区会再次写入，使磁盘上的文件包含新结果；如果您在此期间进行了编辑，缓冲区会保持修改状态供您保存。块运行时不会显示评估提示，但 :eval no、never 或 query 的块会被跳过。未更改的图表会立即从缓存获取。
    • :Org diagrams_clean 会询问后删除当前文件 output_dir 中生成的文件（LANG-HASH8.EXT），这些文件不被该目录中的任何 org 文件链接或引用（打开的缓冲区按其未保存的文本计算）；:Org diagrams_clean dry 只列出它们。您用 :file 自己命名的文件永远不会被删除。
    • 工具运行时不使用 shell（参数列表），除非命令是 shell 片段（多个单词的字符串）或块设置了 :cmd 或 :cmdline，这些是 ob-dot 中的 shell 文本。

    操作

    diagrams_render渲染光标处的图表块（与 C-c C-c 在此处的作用相同）；不适用于其他地方
    diagrams_rerender同上，但忽略缓存
    diagrams_render_buffer渲染缓冲区中的每个图表块
    diagrams_clear_cache删除缓存的渲染
    diagrams_clean删除没有链接的已生成图表

    没有默认按键；使用 :Org <action> 或在 mappings.org 中绑定。

    选项（括号内为默认值）

    languages处理的语言（{ "mermaid", "dot", "plantuml" }）；未包含的语言保留其核心行为
    mermaid{ command（"mmdc"；字符串通过 shell 运行，因此 "npx -y @mermaid-js/mermaid-cli" 可用，或单词列表），args（{}），theme，background，config_file，puppeteer_config }（上述头部参数的默认值）
    dot{ command（"dot"），args（{}）}
    auto_file没有 :file 时自动生成（true）
    output_dir生成名称的目录（"diagrams"）
    format生成名称的扩展名（"png"）
    cache使用缓存（true）
    cache_dirstdpath("cache") .. "/org/diagrams"
    auto_preview预览结果图片（true）
    render_on_save保存后渲染图表块（false）
    cache_max_age未使用的缓存条目保留天数（90；false：永久）
    cache_max_size缓存修剪到的兆字节数（200；false：无限制）

    :checkhealth org 显示安装了哪些渲染器（mmdc、dot、plantuml 或 jar 和 java），结果是否可以预览，以及缓存目录。加载扩展不需要任何工具；缺少工具的块会报告该情况并不插入结果。

    限制

    • 生成的名称随内容变化，因此编辑图表会将其旧文件留在 output_dir 中，直到运行 diagrams_clean。
    • 只跟踪 plantuml 的 include：mermaid 的配置或 CSS 文件，以及 dot 的 image= 或 imagepath 文件，不是缓存键的一部分；更改它们后请使用 diagrams_rerender。
    • 未安装 Graphviz 时，测试中只运行了模拟工具；参数顺序遵循 ob-dot（dot IN -TEXT [args] -o OUT）。
    • 只缓存文件结果。plantuml 的文本输出（:results verbatim，无 :file）由核心移植版处理。
